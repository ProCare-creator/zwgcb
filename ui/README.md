# 页面源码与单文件发布

- `app.html`：可读的页面外壳和原有应用逻辑。保留存储、导出导入、Word 和同步逻辑。
- `ai.js`：第 5 批 AI 页面及客户端交互。
- `ai.css`：AI 页样式。
- `../index.html`：生成并提交的单文件页面。浏览器不请求本目录中的 JS/CSS；静态构建也不上传这些源码。

修改源码后运行 `npm ci`（首次），然后 `npm run build:page`。打包只缩短局部变量名并去掉空白，不做逻辑优化；发布文件上限为 300,000 字节。Cloudflare 部署仍用 `node build.mjs` 复制已生成的页面，不依赖线上安装包。

## 本批交付约定

AI 对话改版按 A / B / C / D 批在 `ai-chat` 开发。每批完成后提交到 GitHub、给出截图和实测数字，用户确认后才进入下一批。只有用户说“可以上线”后才将 APP_VERSION 和 sw.js VERSION 同步升级为 v6.12.0 并合并 main。本批不发布，保留 v6.11.1。

第 A 批的思考摘要仅留在会话内存，正文和可选 `stopReason` 才进入原有记录 / 草稿。`max_tokens` 时正文下方显示截断提示；没有正文则提示重试并保留旧总结。诊断新增是否收到思考内容、结束原因、力度参数状态。前端超时分别为 330 / 660 秒，生成期间尽力保持屏幕常亮。

运行 `npm run test:ui` 检查流式解析、截断、思考不持久化、Wake Lock 生命周期。当前仍是总结 / 探索页签；聊天界面属于第 B 批。

本机真实测试仅通过本地 `wrangler dev --local` 使用虚构材料，线上验证以用户手机为准。不得提前改错主节点做备用验证。

## 插入小批次：从探索提炼假设

保持总结 / 探索页面结构。当前探索至少两条 Claude 回复才显示“提炼假设”，已保存对话均有该入口。每次提炼复用发送确认框，展示本次对话全文和现有假设的编号 / 文字；不会发送当天其他材料。

卡片及编辑状态只存在内存。用户确认加入时才调用原有 `makeHyp` 和 `put`，编号、待验证状态、空证据与手动新建一致，并增加可选 `src:{type:'ai',date,chatId}`。尚未保存的来源对话会在确认时写入原有 `explores`（确认文字已说明），保证刷新后仍可追溯；不会清空当前探索。保存失败可重试，重复点击不会重复分配编号。

“已加入 #编号”定位到假设；来源标记通过 `#ai?day=日期&chat=对话id` 打开原有历史区域。来源被删除时提示不存在。提炼结果不进入草稿、导出或同步；已加入的假设和来源对话正常保存、导出与同步。
