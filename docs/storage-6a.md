# 6a · 本机存储验收

新站（及 localhost）以 IndexedDB 的 `zwgcb/docs` 保存六个集合，复合键为 `[集合,id]`，值为原记录。`control` 只存迁移标记和备份期限、指纹。首次写入、逐条回读核对与切换标记在同一事务内完成。单条新增、修改、删除等待事务完成后才算成功。原有导入、导出、草稿及同步设置不改格式。GitHub Pages 保留原实现。

旧格式备份保留 30 天，到期后下次打开新站时清理；若旧版页面后来改过备份，则保留。首次打开时 IndexedDB 不可用或核对不符，继续使用可读的旧存储。如果已经切换，后来打不开主库，会提示重试并暂停写入，以免用过期备份覆盖最新记录。

在 Chrome 隔离配置、本地回环地址上运行 `node tools/check-storage.cjs`。脚本读取旧提交 `f07610c` 中的真实页面，不依赖网络或模型。可通过 `PLAYWRIGHT_PATH` 与 `CHROME_PATH` 指定 Playwright 和浏览器，`QA_OUTPUT` 指定截图目录。

| 场景 | 本机实测 |
| --- | --- |
| 旧版界面导入 → 新版打开 | 7 条、6 个集合；9 个页面的记录内容一致；实际下载的 JSON 除导出时间外逐字段一致 |

| 大聊天 | 导入 24 条虚构聊天（7,421,011 字节），4.172 秒；刷新到设置页可用 0.253 秒；共 31 条，导出聊天正文逐条相同 |
| 30 天保留期 | 模拟第 31 天重新打开，旧备份被清理；导出结果不变 |
| 数据库不可用 | 首次打开回退，原 7 条可读，新写 1 条刷新后仍在；已迁移设备遇到同样故障时暂停写入 |
| 校验失败 | 有意改变写入值，迁移事务回滚；数据库中正式记录为 0，旧备份未改 |
| 旧站 | 模拟 GitHub Pages 域名：沿用原设置页，未创建 IndexedDB |
