# 6a · 本机存储验收

新站（及 localhost）以 IndexedDB 的 `zwgcb/docs` 保存六个集合，复合键为 `[集合,id]`，值为原记录。`control` 只存迁移标记和备份期限、指纹。首次写入、逐条回读核对与切换标记在同一事务内完成。单条新增、修改、删除等待事务完成后才算成功。导入、导出及同步设置不改格式；聊天草稿的精简格式见下方补充。GitHub Pages 保留原实现。

旧格式备份保留 30 天，到期后下次打开新站时清理；每次启动核对指纹，旧页面的改动成功合并后才更新指纹；合并失败保留备份，下次重试。首次打开时 IndexedDB 不可用或核对不符，继续使用可读的旧存储。如果已经切换，后来打不开主库，会提示重试并暂停写入，以免用过期备份覆盖最新记录。

在 Chrome 隔离配置、本地回环地址上运行 `node tools/check-storage.cjs`。脚本读取生产提交 `97d55e7` 中的真实页面，不依赖网络或模型。可通过 `PLAYWRIGHT_PATH` 与 `CHROME_PATH` 指定 Playwright 和浏览器，`QA_OUTPUT` 指定截图目录。

| 场景 | 本机实测 |
| --- | --- |
| 旧版界面导入 → 新版打开 | 7 条、6 个集合；9 个页面的记录内容一致；实际下载的 JSON 除导出时间外逐字段一致 |
| 核对中刷新 | 原生游标核对期间触发重载；恢复后无缺失、无重复，旧备份原样保留 |
| 大聊天 | 导入 24 条虚构聊天（7,421,011 字节），4.172 秒；刷新到设置页可用 0.253 秒；共 31 条，导出聊天正文逐条相同 |
| 30 天保留期 | 模拟第 31 天重新打开，旧备份被清理；导出结果不变 |
| 数据库不可用 | 首次打开回退，原 7 条可读，新写 1 条刷新后仍在；已迁移设备遇到同样故障时暂停写入 |
| 校验失败 | 有意改变写入值，迁移事务回滚；数据库中正式记录为 0，旧备份未改 |
| 旧站 | 模拟 GitHub Pages 域名：沿用原设置页，未创建 IndexedDB |

现有 42 项自动测试通过；单文件页面 333,236 字节（gzip 103,018 字节）。未配置 D1、未调用云端同步、未发布生产。

## 热修复合回后的补充验收（仅 ai-chat）

运行 `node tools/check-6a-supplement.cjs`。同一浏览器内并排使用旧版和新版页面；服务只监听本机，不访问模型或用户数据。

| 检查 | 实测结果 |
| --- | --- |
| 旧标签页改标题、新增一条聊天 | 新版显示合并 2 条；其余记录逐条相同，再开一次不重复合并 |
| 事务中途强制写入失败 | 保留旧存储；下次启动成功重试，未提前推进指纹 |
| 生成中刷新 | 216,276 字节的对话，生成中草稿 192 字节；刷新后全部历史、用户当轮消息、已收到的正文及输入框文字均恢复 |
| 老格式整段草稿 | 216,551 字节样本转换后，草稿 100 字节；对话正文进入正式记录，未发送输入与待发送附件保留 |
| 原 6a 浏览器回归 | 6 类数据和 9 个页面对照通过；7,421,011 字节聊天导入 4.255 秒、刷新 0.253 秒。过期、禁用数据库及回退场景通过 |

聊天发送前先持久保存用户消息。草稿只保留待发送的输入、附件，以及未保存回复和它的位置。正式记录保存成功后，仅清除与之匹配的草稿内容。实测草稿大小针对上述样本，并非对回复或附件进行截断。

补充后的单文件页面为 335,596 字节（gzip 103,872 字节）；Worker 和 UI 自动测试 46 项通过。
